# PageGuard 確定仕様

ページ単位の BASIC 認証プラグイン。**ページごとに独立した ID / パスワード**を持てる点が、
サイト全体に1組しか持てない既存プラグインとの違い。

実装時の制約（プレフィックス・禁止事項・検証方法）は [`../CLAUDE.md`](../CLAUDE.md) を参照。

## 1. 適用範囲

- **ページ単位**で、ページごとに ID / パスワードを設定する
- **1ページにつき1組**。複数組の登録は v1.1 以降の検討事項（初版のスコープ外）
- 設定は対象投稿の**編集画面**で行う

## 2. 対象の投稿タイプ

- 公開投稿タイプ全般を対象にできる
- **設定画面で選択**し、**既定は固定ページのみ**

## 3. パスワードの保存

- `password_hash` で保存し `password_verify` で検証する
- **設定済みパスワードの再表示は不可**（忘れた場合は再設定）
- ユーザー名は平文で保存してよい。文字列比較は `hash_equals` を使う

## 4. 環境差の吸収

- `PHP_AUTH_USER` / `PHP_AUTH_PW` に加え、`HTTP_AUTHORIZATION` と `REDIRECT_HTTP_AUTHORIZATION` を
  **自前で base64 デコード**して受け取る（CGI/FastCGI 経由では `PHP_AUTH_*` が入らないため）
- 設定画面に**受信可否の診断**を出す。受け取れない環境向けに `.htaccess` のスニペットを表示する
- **`.htaccess` の自動書き換えはしない**
- サイトが **HTTPS でない場合は診断パネルで警告**する（BASIC 認証は毎リクエストで資格情報を送るため）

## 5. 漏れ対策（塞ぐ経路）

1. HTML 本体（`template_redirect`）
2. **REST API**
3. **フィード**
4. **検索結果・アーカイブからの除外**
5. **サイトマップからの除外**
6. **キャッシュ抑止**（`DONOTCACHEPAGE` の定義と `nocache_headers()`）

**メディアファイルへの直リンクは原理的に守れない**（Web サーバーが WordPress を経由せず返すため）。
README と管理画面の両方に明記する。

## 6. ログイン中の扱い

その投稿の**編集権限（`edit_post`）を持つユーザー**は認証をスキップする。

## 7. 総当たり対策

- **IP 単位**で失敗回数を transient に記録し、規定回数で一定時間ロックする
- **回数・ロック時間は設定画面で変更できる**
- **管理画面からロックを解除できる**

## 8. 名称

**PageGuard**（`PageLock` は EditLock と混同するため不採用）。

## 9. 設定画面の内容

- 対象投稿タイプの選択
- 失敗回数 / ロック時間
- 受信診断（＋ HTTPS 警告、必要なら `.htaccess` スニペット）
- ロック中 IP の解除
- **保護中ページの一覧**

## 10. その他の前提

- 401 のキャンセル時は**日本語の固定文言**を表示し、`pggd_` プレフィックスのフィルターで差し替え可能にする。
  realm はサイト名を使う
- `uninstall.php` は**空**（アンインストールでデータを消さない）
- **公開期間・有効期限の機能はスコープ外**
- 支援・依頼リンクを**初版から3箇所**に入れる（`plugin_row_meta` / ダッシュボードウィジェット / `admin_footer_text`）

## 由来

hkcsystem の `inc/tools/customer-file-importer.php` にある約40行の実装が発想元。
そこからの変更点は次の5つ:

| 由来元 | 公開版 |
|---|---|
| 平文でパスワードを保存 | ハッシュ化して保存 |
| `PHP_AUTH_USER` のみ参照 | 自前デコード＋受信診断 |
| HTML 本体のみ保護 | 裏口5経路も塞ぐ |
| 失敗回数の制限なし | IP 単位のロック |
| 固定ページのみ | 投稿タイプを選択可能 |
